# CLASS PARTY 40

약 40명의 학생이 각자 스마트폰 브라우저로 접속해 **하나의 3D 경기장**에서 실시간으로 겨루는 교실용 파티 게임입니다.
설치 없이 QR 코드나 6자리 코드로 들어오고, 교사는 프로젝터 화면에서 진행합니다.

현재 **1~3단계(미니게임 11종, 화학 모드, 문제은행)** 까지 구현되어 있습니다. 아래 [구현 현황](#구현-현황)을 먼저 확인하세요.

## 빠른 시작

Node.js 20 이상이 필요합니다(22 권장). macOS(M4 Mac mini 포함), Windows, Linux에서 같은 명령으로 실행됩니다.

```bash
npm install
```

### 수업용 실행(권장): 한 포트로 전부 제공

```bash
npm run build
```

```bash
PORT=3000 npm start
```

터미널에 `같은 Wi-Fi의 기기에서: http://192.168.x.x:3000` 주소가 출력됩니다.

### 개발용 실행: 코드 수정 시 자동 반영

```bash
npm run dev
```

서버는 3001번, 화면은 5173번 포트에서 열립니다. 브라우저에서 `http://localhost:5173` 을 엽니다.

### Docker

```bash
docker compose up --build
```

`http://<서버 주소>:3000` 으로 접속합니다. 서버 한 대(프로세스 하나)가 게임 서버와 웹 화면을 함께 제공합니다.

## 수업에서 쓰는 방법

1. 교사 PC에서 `http://localhost:3000` → **교사: 방 만들기** → 라운드 수와 미니게임을 고르고 방을 만듭니다.
2. 프로젝터에 **입장 코드와 QR 코드**가 크게 표시됩니다. QR 주소는 같은 Wi-Fi용 IP 주소로 자동 변환됩니다.
3. 학생은 QR을 찍거나 주소를 입력한 뒤 닉네임과 캐릭터 색을 고르고 입장합니다. 대기실에서 미리 뛰어다니며 조작을 익힙니다.
4. 교사가 **게임 시작**을 누르면 추첨 → 카운트다운 → 경기 → 결과가 자동으로 반복되고, 마지막에 시상식이 열립니다.
5. 진행 중에는 일시정지 / 넘기기 / 강제 종료 / 학생 내보내기가 가능하고, 결과는 CSV(엑셀)로 내려받습니다.

**스마트폰 접속 조건**: 학생 기기와 교사 PC가 같은 네트워크에 있어야 합니다. 학교 Wi-Fi가 기기 간 통신을 막는다면(AP 격리)
교사 PC의 핫스팟을 쓰거나 Docker 이미지를 외부 서버에 올리세요. 방화벽에서 해당 포트(3000)를 허용해야 합니다.

## 동기화 방식

- **서버 권한**: 이동·충돌·체크포인트·결승 판정·점수는 전부 서버가 계산합니다. 클라이언트는 입력(방향, 버튼)만 보냅니다.
- **입력 1개 = 물리 1걸음**: 클라이언트가 30Hz로 번호가 붙은 입력을 보내고, 서버는 받은 입력마다 한 걸음씩 진행합니다.
  틱당 평균 1개(순간 최대 4개)만 허용하는 토큰 버킷으로 속도 조작을 막습니다.
- **클라이언트 예측**: 내 캐릭터는 같은 Rapier 물리로 즉시 움직이고, 서버 상태가 오면 어긋났을 때만 되감아 다시 계산합니다.
  작은 오차는 화면에서 부드럽게 줄입니다.
- **보간**: 다른 캐릭터는 15Hz 스냅샷 두 개 사이를 약 100ms 지연으로 보간합니다.
- **통신량**: 스냅샷은 플레이어당 9바이트(위치 2cm 단위)입니다. 40명일 때 한 학생이 받는 양은 약 8KB/s입니다.
- **재접속**: 탭마다 토큰을 저장해 새로고침·연결 끊김 후 같은 자리와 점수로 돌아옵니다. 같은 토큰으로 다시 접속하면 이전 연결은 끊깁니다.
  브라우저를 완전히 닫았다면 같은 닉네임으로 다시 들어오면 자리를 이어받습니다.

## 테스트 방법

### 여러 브라우저로 직접 확인

1. 서버를 실행하고 한 창에서 방을 만듭니다.
2. 다른 탭·창·브라우저를 여러 개 열어 `http://localhost:3000/?code=입장코드` 로 각각 입장합니다(탭마다 별도 학생으로 인식).
3. 한 창에서 움직이면 다른 창에서 같은 위치로 보이는지, 게임 시작 후 전원이 같은 맵으로 넘어가는지 확인합니다.

### 부하 테스트(봇)

서버를 켠 상태에서 실행합니다. 주소와 인원은 바꿀 수 있습니다.

```bash
npm run loadtest -- --bots 40 --seconds 20 --url http://localhost:3000
```

`--game spinner`(또는 `tiles`, `last`, `bomb`, `treasure`, `sumo`, `tail`, `maze`, `answer`)로 게임을, `--mode chem --game chemmaze` 처럼 화학 모드를 게임을 고르고, `--smart` 를 붙이면 봇이 발판과 회전봉을 보고 피합니다.
`--wait 30` 을 주면 봇이 들어온 뒤 30초 기다렸다 시작하므로, 출력된 방 코드로 실제 휴대폰을 함께 넣어 볼 수 있습니다.

### 완주·판정 검증

```bash
npm run racebot -w server -- --url http://localhost:3000
```

장애물을 보고 피하는 봇 1명과 직진만 하는 봇 3명이 실제 서버에서 경기하고 결과표를 출력합니다.

### 측정 결과

4코어 리눅스 컨테이너에서 서버와 봇을 같은 기계에 두고 레이스 중 20초씩 측정한 값입니다.

| 봇 수 | 틱 처리 평균 | 틱 처리 p99 | 실제 틱 속도 | 서버 CPU(1코어 대비) | 메모리 | 서버 송신량 | 학생 1명 수신량 | 스냅샷 간격 p99 |
|---|---|---|---|---|---|---|---|---|
| 10 | 0.55ms | 1.6ms | 30.0Hz | 4.7% | 132MB | 39KB/s | 3.7KB/s | 68.9ms |
| 20 | 0.67ms | 1.8ms | 30.0Hz | 5.6% | 137MB | 105KB/s | 5.0KB/s | 67.9ms |
| 40 | 0.94ms | 2.5ms | 30.0Hz | 7.4% | 143MB | 315KB/s | 7.7KB/s | 69.6ms |

틱 예산 33.3ms 대비 여유가 30배 이상입니다. 함께 확인한 것: 봇 38~39명과 실제 브라우저가 한 경기장에 40명으로 그려짐,
정원 초과 입장 거절, 경기 중 입장 시 관전, 새로고침 후 같은 자리 복귀, 중복 접속 시 이전 탭 종료, 완주 봇의 결승 판정과 점수.

**아직 측정하지 못한 것**: 실제 스마트폰 40대의 FPS와 학교 Wi-Fi에서의 지연입니다. 위 값은 한 기계 안의 봇 기준이라
무선 구간 지연과 휴대폰 GPU 성능은 반영되지 않았습니다. 수업 전에 실제 기기 몇 대와 봇을 섞어 한 번 돌려 보세요.
화면이 느린 기기는 화질이 자동으로 한 단계씩 내려가고, ⚙ 버튼으로 직접 고를 수도 있습니다.

## 구현 현황

### 구현 완료

- 교사: 방 생성, 6자리 코드, QR, 미니게임·라운드 설정, 시작 / 일시정지 / 넘기기 / 강제 종료, 참가자 목록·내보내기, 실시간 순위, 결과 CSV
- 학생: 닉네임·색 선택, 코드/QR 입장, 3D 대기실, 자동 맵 전환, 라운드 결과와 누적 순위
- 최대 40명 서버 권한 동기화, 클라이언트 예측, 보간, 재접속, 중복 닉네임·중복 접속 처리, 경기 중 입장 관전
- 캐릭터: 절차적으로 만든 오리지널 캐릭터(테두리, 밝은 배, 5가지 머리 장식), 걷기·점프·넘어짐·승리·패배 동작과 표정, 닉네임표(멀면 숨김)
- 맵 꾸밈: 셰이더로 그린 체크무늬 바닥과 흰 테두리, 줄무늬 회전봉, 눈 달린 미는 벽, 체크포인트 아치, 풍선·고리, 구름 바다
- 조작: 가상 조이스틱, 점프 버튼, 3인칭 카메라, 키보드·마우스, 세로 화면 안내
- 미니게임 11종(놀이 모드 10종 + 화학 모드 전용 1종)
  - **교실 탈출 달리기**(레이스): 회전봉, 움직이는 벽, 점프 발판, 흔들다리, 징검다리 낙하 구간, 체크포인트 5개
  - **빙글빙글 원판**(생존): 낮은 봉은 점프, 높은 봉은 점프 금지. 봉이 점점 빨라지고 원판 바깥쪽이 두 번 떨어져 나감
  - **와르르 타일**(생존): 64칸 발판이 깜빡인 뒤 물결처럼 사라져 마지막 한 칸만 남음
  - **좁아지는 섬**(생존): 바깥 고리부터 한 칸씩 무너지고 회전봉이 늘어나며 빨라짐
  - **펑펑 광장**(생존): 폭탄이 범위를 빨간 원으로 예고한 뒤 터짐. 원 밖으로 피하거나 벽 뒤에 숨으면 안전. 후반엔 폭탄이 잦아지고 광장 바깥 고리가 무너짐
  - **반짝 보물섬**(수집): 60초 동안 보석을 먼저 집는 사람이 득점. 회전봉 안쪽과 건너편 섬에는 3점짜리 큰 보석. 떨어지면 3점 감점
  - **영차영차 씨름판**(대결): 밀기 버튼(쿨타임 1.2초)으로 앞의 상대를 밀어냄. 판이 두 번 줄어듦
  - **꼬리 지키기**(대결): 세 명 중 한 명이 꼬리를 달고 시작. 닿으면 꼬리가 넘어가고, 달고 있던 시간만큼 점수 + 끝까지 지키면 보너스 20점
  - **열렸다 닫혔다 미로**(레이스): 가로벽 6줄을 통과. 줄마다 틈 3개 중 하나는 항상 열려 있고 둘은 문이 여닫힘
  - **정답 발판 배틀**(퀴즈): 문제 6개. 정답 보기의 발판으로 달려가면 오답 발판이 잠깐 사라짐. 틀려도 다음 문제에 참가. 놀이 모드 문제는 암산·색 글자·큰 수·기억력·개수 세기
- **화학 모드(물질과 에너지 3·4단원)**
  - 기본 문제은행 41문제: 3단원 20문제(반응 엔탈피, 열화학 반응식, 헤스 법칙, 엔트로피, 자발성), 4단원 21문제(반응 속도, 속도식, 반응 차수, 속도 상수, 활성화 에너지, 촉매, 반감기). 쉬움·보통·어려움, 정답과 해설 포함
  - **정답 발판 배틀**: 화학 모드에서는 문제은행에서 5문제를 출제하고 채점 뒤 해설을 보여 줌
  - **정답의 문**(화학 모드 전용 레이스): 벽마다 문제가 걸려 있고 빛의 문이 셋. 정답 보기가 걸린 문은 통과, 오답 문은 튕겨 나가 1.2초쯤 넘어짐. 보기 순서가 학생마다 달라 앞사람을 따라가도 소용없음
  - 화학 모드의 추첨에는 순수 조작 게임도 섞이고, 학습형 게임이 절반쯤 나오도록 가중치를 둠. 같은 경기에서 이미 나온 문제는 뒤로 미룸
  - 정답과 해설은 채점하는 순간에만 서버가 보냄(미리 받는 문제 데이터에는 정답이 없음)
- **문제은행 편집 화면**: 문제 추가·수정·삭제, 단원·난이도 필터, 파일로 내보내기/가져오기, 기본 문제로 되돌리기. 교사 브라우저에 저장되고 방을 열 때 서버에 적용됨. 방 만들기와 교사 화면에서 출제 단원·난이도 선택
- 생존 게임 공통: 떨어지면 탈락해 관전으로 전환, 오래 버틴 순서로 순위(같은 순간 탈락은 공동 순위), 한 명 남으면 종료
- 추첨 → 카운트다운 → 경기 → 결과 → 시상식 흐름, 순위별 점수(100 / 95 / 90 / 이후 2점씩), 미완주자 진행도 점수
- 성능: 캐릭터 인스턴싱(40명 드로우콜 7~8회), 화질 3단계와 자동 조절, WebGL 중단 안내

- 방 정보는 서버 메모리에만 있어 **서버를 재시작하면 진행 중인 방이 사라집니다.**

### 알려진 문제

- 밀치기와 꼬리 뺏기는 서버에서만 판정합니다. 밀린 사람 화면에서는 위치가 보정되며 따라오므로, 지연이 큰 환경에서는 살짝 늦게 밀리는 느낌이 날 수 있습니다.
- 놀이 모드의 정답 발판 문제(암산 등)는 맵 데이터에 정답과 함께 들어 있어 개발자 도구로 미리 볼 수 있습니다. 화학 모드 문제는 정답을 미리 보내지 않습니다.
- 문제은행은 교사 브라우저(localStorage)에 저장됩니다. 다른 컴퓨터에서 쓰려면 파일로 내보내 가져와야 합니다.
- 기본 문제 41개는 교육과정 성취기준을 바탕으로 작성한 초안입니다. 수업 전에 문제은행 화면에서 한 번 훑어보고 교과서 표현에 맞게 고쳐 쓰세요.
- 결과 CSV에는 게임별 점수만 들어가고 문항별 정답률은 아직 없습니다.

- 캐릭터끼리 밀어내는 힘은 서버에서만 계산합니다. 출발 직후처럼 붐비는 곳에서는 내 캐릭터가 살짝 밀려 보정되는 느낌이 있습니다.
- Docker 이미지는 이 개발 환경에 Docker 데몬이 없어 **빌드해 보지 못했습니다.** Dockerfile과 같은 순서의 설치·실행은 Docker 없이 따로 확인했습니다.
- 글꼴(Jua, Gowun Dodum)은 Google Fonts에서 불러옵니다. 인터넷이 없는 망에서는 기기 기본 글꼴로 표시됩니다.

## 미니게임 추가하는 법(2단계용)

1. `shared/src/levels/` 에 맵 생성 함수를 만들고 `shared/src/games.ts` 의 해당 항목에 `buildLevel` 과 `implemented: true` 를 지정합니다.
2. `server/src/minigames/` 에 `MinigameServer` 를 구현합니다. `onTick`(규칙), `canMove`, `isOver`, `outcome`(순위·점수) 네 가지입니다.
3. `server/src/minigames/index.ts` 의 `REGISTRY` 에 등록합니다. 추첨·점수 합산·결과 화면은 그대로 동작합니다.
   생존형은 `survivalGame('id')`, 수집형은 `collectGame('id')` 한 줄이면 됩니다.
4. 사라지는 발판(`tiles`), 폭탄(`bombs`), 보물(`items`), 회전봉 일정은 맵 데이터에 시각으로 적습니다. 서버와 클라이언트가 같은 시각표를 보므로 추가 통신이 없습니다.
5. 맵에 새 종류의 장치가 필요하면 `shared/src/level.ts` 와 `sim.ts`(판정), `client/src/three/LevelView.tsx`(그리기)에 추가합니다.
